# Assessment architecture

The assessment layer is a self-contained Node toolkit under `assessment/`, kept
separate from the World Monitor app so it is maintainable and does not alter the
target's build. Everything runs on plain Node (no extra dependencies).

```
assessment/
  run.mjs                     # one-command pipeline: collect evidence -> report
  engine/
    discover.mjs              # attack-surface discovery (reads the repo)
    cvss.mjs                  # CVSS v3.1 calculator (self-checked vs reference vectors)
    collect-evidence.mjs      # runs PoC + regression suite, writes evidence.json (hashes, timestamps)
    report.mjs                # assembles assessment.json + report.md + report.html + dashboard data.js
  poc/
    f1-rss-proxy-poc.mjs      # BEFORE/AFTER controlled PoC (baseline vs remediated)
  tests/
    f1-rss-proxy.security.test.mjs   # 9-case F1 regression suite
  data/
    findings.json             # canonical, hand-authored finding lifecycle records
    evidence.json             # generated: real PoC + test results
    assessment.json           # generated: single source of truth for the dashboard
  dashboard/
    index.html                # security console UI (Overview, Attack Surface, Findings, F1, Remediation, Reports, Demo)
    data.js                   # generated: window.ASSESSMENT (loads over file://)
  reports/
    report.md / report.html   # generated reports
  docs/                       # methodology, findings, f1-rss-proxy, remediation, retest, architecture, scope
```

## Data flow

`findings.json` (authored) + live `discover()` + `cvss.f1Score()` + `evidence.json`
(generated by running the checks) → `report.mjs` → `assessment.json` → dashboard +
`report.{md,html}`. No result is hardcoded; evidence is produced by executing the
PoC and the regression suite at collection time.

## Relationship to the target

The only change to the World Monitor application itself is the F1 remediation in
`src-tauri/sidecar/local-api-server.mjs` (plus two existing sidecar tests updated to
opt their fixture hosts into the new allowlist). The original behavior is preserved
on tag `BASELINE-SIH26163`.
